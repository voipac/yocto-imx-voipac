# Example project for building Yocto for Voipac iMX boards

## Prerequisities
Build was verified on Ubuntu 20.04.
Install docker papckage on your system.


## Secure boot image build
Please follow below steps how to build and flash imx93 image with secure boot integrated:

### Preresiquities
1. download CST tool: https://www.nxp.com/webapp/sps/download/license.jsp?colCode=IMX_CST_TOOL
2. unpack it on machine where yocto will be compiled (e.g. `/home/user/cst`)
3. navigate to the `/home/user/cst/keys`)
4. create a text file called "serial", which contains 8 digits. It will be used for the certificate serial numbers. (e.g.: `echo 12345678 > serial`)
5. create a text file called "key_pass.txt", which contains two lines of a password repeated twice.
This password will be used to protect the generated private keys.
e.g.: 
```
echo my_secret_password >  key_pass.txt
echo my_secret_password >> key_pass.txt
```
6. to generate the PKI tree, run the following: `./ahab_pki_tree.sh`
   and complete the interactive questions. For example:

```
Do you want to use an existing CA key (y/n)?: n
Key type options (confirm targeted device supports desired key type):
Select the key type (possible values: rsa, rsa-pss, ecc)?: ecc
Enter length for elliptic curve to be used for PKI tree:
Possible values p256, p384, p521: p384
Enter the digest algorithm to use: sha384
Enter PKI tree duration (years): 20
Do you want the SRK certificates to have the CA flag set? (y/n)?: n
```

7. generate Super Root Key (SRK) table
```
cd ../crts
../linux64/bin/srktool -a -d sha256 -s sha384 -t SRK1234table.bin -e SRK1234fuse.bin -f 1 -c SRK1_sha384_secp384r1_v3_usr_crt.pem,SRK2_sha384_secp384r1_v3_usr_crt.pem,SRK3_sha384_secp384r1_v3_usr_crt.pem,SRK4_sha384_secp384r1_v3_usr_crt.pem
```
For the SoC i.MX93, the Message Digest algorithm (option —d) is sha256, while the Signature Digest algorithm (option -s) must match the one from the PKI generation.
8. create file in root of cst directory called `cfs_ahag.cfg` with following content:
```
#Header
header_version=1.0
#Install SRK
srktable_file=SRK1234table.bin
srk_source=SRK1_sha384_secp384r1_v3_usr_crt.pem
srk_source_index=0
srk_source_set=OEM
srk_revocations=0x0
#Install Certificate
sgk_file=
sgk_permissions=
```
This will be used by Yocto to point to proper SRK table and keys.

9. run `build_image_container.sh pro imx93` script to build iMX93 Voipac devkit image in docker container
10. when image is ready copy from build machine files: `signed-imx-boot-imx93-voipac-sd.bin-flash_singleboot` and `voipac-image-imx93-voipac.rootfs.wic.zst` to e.g. `/home/user/output`
11. use following script to flash image to development kit:
```
#!/bin/sh

sudo ./uuu -b emmc_all voipac-image-imx93-voipac.rootfs.wic.zst
# flash secure imx-boot
sudo ./uuu uuu-hab.lst
```

where `uuu-hab.lst` have following content:
```
uuu_version 1.2.39

SDPS: boot -f signed-imx-boot-imx93-voipac-sd.bin-flash_singleboot


FB: ucmd setenv fastboot_dev mmc
FB: ucmd setenv mmcdev ${emmc_dev}
FB: ucmd mmc dev ${emmc_dev}
FB: flash bootloader signed-imx-boot-imx93-voipac-sd.bin-flash_singleboot
FB: ucmd if env exists emmc_ack; then ; else setenv emmc_ack 0; fi;
FB: ucmd mmc partconf ${emmc_dev} ${emmc_ack} 1 0
FB: Done

```

for more info about flashing see: https://wiki.voipac.com/index.php?title=iMX8M_Industrial_Flashing_procedure
12. boot your new build image and hit any key during startup to stop in u-boot
13. program the SRK (public keys) to the SOC e-fuses
- navigate to the `cst/crts directory`
- run `od -t x4 SRK1234fuse.bin`
- output will look like:
```
0000000 f43dab72 1b8eda1a 1ddd596d a1cb9682
0000020 0bf178ea 32308483 d596393c ca21a9b
```
based on above use following (please adjust to numbers generated by your keys) run in u-boot console:
```
  => fuse prog 16 0 0xf43dab72
  => fuse prog 16 1 0x1b8eda1a
  => fuse prog 16 2 0x1ddd596d
  => fuse prog 16 3 0xa1cb9682
  => fuse prog 16 4 0x0bf178ea
  => fuse prog 16 5 0x32308483
  => fuse prog 16 6 0xd596393c
  => fuse prog 16 7 0xca21a9b
```
14. restart board and stop in u-boot by pressing any key and run `ahab_status`. Output should look like:
```
=> ahab_status
  Lifecycle: 0x00000008, OEM Open

          No Events Found!
```
In case there are some events something is not right with the keys (or fuses are not flashed)
15. please verify board can boot to userspace
16. close the device by again stop execution in uboot and run :
```
ahab_close
```
after that restart the board and run again:
```
=> ahab_status
  Lifecycle: 0x00000020, OEM Closed

          No Events Found!
```

After that step device is locked and only images signed with private keys will boot on this device.

For more info: https://github.com/nxp-imx/uboot-imx/blob/lf_v2023.04/doc/imx/ahab/guides/mx8ulp_9x_secure_boot.txt
